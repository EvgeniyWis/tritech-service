# ТрайтэкСервис — информационная система технического блока ООО «Трайтэк»

Рабочая реализация курсового проекта: три связанных модуля в одной системе.

| Модуль | Что делает |
|---|---|
| **Консалтинг** | каталог услуг и консультантов, расчёт свободных слотов, запись с удержанием слота (30 мин), оплата через ЮKassa (webhook), перенос и отмена с возвратом по правилам, календарь и расписание консультанта, заключения (версии), отзывы с модерацией, напоминания |
| **Разработка** | проекты (в т. ч. по итогам консультации), команда проекта, задачи, доска Kanban с drag-and-drop, учёт времени, прогресс проекта по оценкам, комментарии и вложения |
| **Техподдержка** | заявки с приоритетами и SLA (рабочее/календарное время), автоназначение по нагрузке, публичные ответы и внутренние заметки, шаблоны ответов, вложения, эскалация в разработку со сквозной связью «заявка ↔ задача» |

Кроме того: авторизация и регистрация (подтверждение e-mail, блокировка после 5 неудачных попыток, восстановление пароля, согласие 152‑ФЗ), 7 ролей с многоролевыми пользователями, сводка директора, 8 отчётов (XLSX/CSV), администрирование (пользователи, справочники, настройки, журнал действий, резервные копии, фоновые задания).

Интерфейс сделан по макетам Figma «ТрайтэкСервис — макеты интерфейса» (токены, компоненты Button / Badge / NavItem / KpiCard / TaskCard / Topbar / Sidebar; экраны «Сводка директора», «Доска задач», «Список заявок с SLA», «Карточка заявки», «Мастер записи»).

## Стек

* Frontend: HTML5, CSS3, нативный JavaScript (ES‑модули, SPA с hash‑маршрутизацией, без сборки и зависимостей).
* Backend: PHP 8.2 без фреймворка (собственные роутер, MVC‑слои «контроллеры → сервисы → PDO»), JSON REST API.
* БД: MySQL 8 / MariaDB 10.4+ (30 таблиц, 4 представления, триггеры запрета пересечения записей).
* Интеграции: ЮKassa API v3 (песочница включается автоматически при пустых ключах), Jitsi Meet (ссылки на видеовстречи), SMTP (собственный клиент; без SMTP письма пишутся в `storage/mails`).
* Всё, что нужно сверх стандартных расширений PHP (XLSX, SMTP, резервные копии), реализовано в коде — Composer не требуется.

## Быстрый старт (Windows + XAMPP)

```bat
start.bat
```

Скрипт запускает MariaDB из XAMPP, создаёт БД `tritech_service` с демо‑данными (если её ещё нет) и поднимает веб‑сервер на **http://127.0.0.1:8200** (порт 8080 на некоторых Windows зарезервирован системой).

Вручную:

```bash
php database/install.php --demo        # создать БД и наполнить демо-данными (--force — пересоздать)
php -S 127.0.0.1:8200 -t public public/index.php
```

## Настройка

Переопределения кладутся в `config/config.local.php` (массив, сливается с `config/config.php`):

```php
<?php
return [
    'app' => ['url' => 'https://service.example.ru', 'debug' => false, 'lazy_cron' => false],
    'db'  => ['host' => '127.0.0.1', 'name' => 'tritech_service', 'user' => 'tritech', 'pass' => '***'],
    'mail' => ['smtp_host' => 'smtp.example.ru', 'smtp_port' => 587, 'smtp_user' => '…', 'smtp_pass' => '…', 'smtp_secure' => 'tls'],
    'yookassa' => ['shop_id' => '…', 'secret_key' => '…', 'return_url' => 'https://service.example.ru/#/my/appointments'],
];
```

* **ЮKassa.** Пока `shop_id`/`secret_key` пусты, работает песочница: платёжная страница имитируется приложением и вызывает ту же обработку, что и webhook. С ключами создаётся настоящий платёж (редирект на форму ЮKassa), а HTTP‑уведомление `POST /api/payments/webhook` не принимается «на веру» — статус перепроверяется запросом `GET /payments/{id}`. Возвраты выполняются через `POST /refunds`. В личном кабинете ЮKassa укажите URL уведомлений `https://<хост>/api/payments/webhook` (события `payment.succeeded`, `payment.canceled`).
* **`app.debug`** — в режиме отладки ссылки подтверждения e‑mail и сброса пароля возвращаются в ответе API (удобно без SMTP). В продуктиве выключить.
* **Бизнес‑правила** (шаг сетки слотов, перерыв, срок удержания, пороги возврата, SLA‑параметры и т. п.) редактируются в интерфейсе: «Настройки» и «Справочники → Приоритеты и SLA».

## Фоновые задания

| Задание | Что делает | Периодичность |
|---|---|---|
| `cancel_unpaid` | освобождает слоты неоплаченных записей | 5 мин |
| `send_reminders` | напоминания за 24 ч и за 1 ч | 15 мин |
| `check_sla` | предупреждения и нарушения SLA, автозакрытие решённых заявок через 72 ч | 5 мин |
| `check_tasks` | уведомления о сроках и просрочке задач | 1 ч |
| `backup` | резервная копия БД (хранится 14 дней) | ежедневно |

```bash
*/5 * * * * php /path/app/cron/run.php cancel_unpaid
*/5 * * * * php /path/app/cron/run.php check_sla
*/15 * * * * php /path/app/cron/run.php send_reminders
0 * * * * php /path/app/cron/run.php check_tasks
0 3 * * * php /path/app/cron/run.php backup
```

В Windows — «Планировщик заданий» с действием `php.exe cron\run.php <задание>`. Если планировщик не настроен, при `app.lazy_cron = true` (по умолчанию) задания запускаются из обычных запросов не чаще раза в 5 минут; вручную их можно запустить в «Резервные копии и cron». Освобождение неоплаченных слотов дополнительно выполняется «лениво» при каждом расчёте слотов и записи.

## Развёртывание

* **Apache**: корень сайта — каталог `public`, `AllowOverride All` (в `public/.htaccess` уже есть правила).
* **nginx**: `location / { try_files $uri /index.php; }` + php‑fpm.
* Каталог `storage/` (вложения, письма, копии, логи) должен быть доступен PHP на запись и **не** публиковаться.
* Для HTTPS cookie сессии получает флаг `Secure` автоматически; заголовки безопасности (CSP, X‑Frame‑Options, Referrer‑Policy) выставляются в `public/index.php`.

## Безопасность (кратко)

bcrypt‑хэши паролей; блокировка входа на 15 мин после 5 неудачных попыток; одноразовые токены подтверждения/сброса (хранятся в виде SHA‑256); регенерация идентификатора сессии при входе; CSRF‑токен для всех изменяющих запросов; PDO с подготовленными выражениями; вывод в DOM только через `textContent`; проверка прав на уровне ресурса (запись, заявка, проект, задача, вложение); загрузка файлов — белый список расширений, лимит 10 МБ, случайные имена вне публичного каталога; webhook ЮKassa проверяется обратным запросом статуса.

## Тесты

```bat
tests\run_all.bat
```

* `tests/sla_test.php` — модульные проверки расчёта SLA (рабочее/календарное время, выходные, согласованность функций).
* `tests/api_test.py` — 157 проверок API: авторизация, слоты, запись/оплата/webhook, перенос, отмена и возвраты (100/50/0 %), истечение удержания, напоминания, права доступа по ролям, заявки/SLA/автоназначение/эскалация, проекты и задачи, отчёты, администрирование.
* `tests/e2e.py` — 41 сквозная проверка в браузере (Playwright + Chrome): регистрация, мастер записи, оплата, перенос и отмена, заявки, работа специалиста, drag‑and‑drop на доске, администрирование, мобильная вёрстка.
